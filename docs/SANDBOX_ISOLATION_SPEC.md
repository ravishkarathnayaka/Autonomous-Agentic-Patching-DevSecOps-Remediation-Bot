# Ephemeral Sandbox Multi-Platform Isolation Specification

This document outlines the architecture, configuration parameters, and execution guarantees for ephemeral sandboxes utilized to verify autonomous patches generated by the bot.

---

## 1. Supported Isolation Engines

| Engine | Isolation Level | Cold Start Latency | Primary Target Environment |
| :--- | :--- | :--- | :--- |
| **Docker (runc)** | Process Namespace & Cgroups | ~800ms | Local Development & GitHub Actions |
| **gVisor (runsc)** | User-space Kernel Emulation | ~1.2s | High-Assurance CI/CD Clusters |
| **Podman (Rootless)** | User Namespaces & Rootless Cgroups | ~900ms | Restricted Enterprise Kubernetes Nodes |
| **Firecracker MicroVM** | Hardware KVM Hypervisor | ~120ms | Multi-tenant SaaS Production Environments |

---

## 2. Docker / gVisor Security Configuration

All sandboxed executions must instantiate containers with the following baseline flags:

```bash
docker run --rm \
  --network none \
  --read-only \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  --security-opt seccomp=/etc/docker/seccomp-profile.json \
  --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  --memory 2g \
  --memory-swap 2g \
  --cpus 2.0 \
  --pids-limit 100 \
  --user 10001:10001 \
  -v /var/run/patch_workspace:/workspace:ro \
  patch-verifier:latest \
  pytest /workspace/tests
```

---

## 3. Seccomp Syscall Filtering Policy

The custom seccomp profile blocks hazardous syscalls known to facilitate container breakout, privilege escalation, and kernel tampering:

### Blocked Syscalls:
- `ptrace` (Process tracing and memory injection)
- `bpf` (Extended Berkeley Packet Filter injection)
- `keyctl` (Kernel keyring manipulation)
- `kexec_load` / `kexec_file_load` (Kernel replacement)
- `mount`, `umount2` (Filesystem alteration)
- `clone3` with disallowed namespace flags

---

## 4. Execution Lifecycle & Determinism

1. **Workspace Snapshot:** The target repository is cloned into a temporary ramdisk (`tmpfs`).
2. **Patch Application:** The proposed patch diff is applied using `git apply --check`.
3. **Hermetic Test Execution:** Unit tests and regression suites run completely disconnected from the Internet (`--net none`).
4. **Exit Code & Artifact Extraction:** Test output, stderr, and code coverage reports are serialized to JSON.
5. **Clean Destruction:** Container and ramdisk workspace are forcefully purged.

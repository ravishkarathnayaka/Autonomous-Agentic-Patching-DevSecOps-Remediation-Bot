# DevSecOps Software Supply Chain Security Whitepaper

This whitepaper details the supply chain security mechanisms implemented within the **Autonomous Agentic Patching & DevSecOps Remediation Bot**, aligning with **NIST SP 800-218 (SSDF)** and **SLSA Level 3** requirements.

---

## 1. Threat Landscape & Executive Summary

Modern software organizations face unprecedented risks from supply chain attacks, including:
- Malicious dependency typosquatting
- Compromised upstream packages
- CI/CD build infrastructure tampering
- Unverified transitive dependencies

The Autonomous Patching Bot ensures every remediated package and patched source file preserves cryptographic provenance and dependency integrity.

---

## 2. Core Pillars of Supply Chain Security

### 2.1 Software Bill of Materials (SBOM) Generation
The bot natively generates industry-standard **CycloneDX v1.5** and **SPDX v2.3** SBOMs during both discovery and post-patch validation:
- Tracks direct and transitive packages.
- Records package hashes (SHA-256) and official Package URLs (PURL).
- Identifies component licenses and alerts on copyleft exposure.

### 2.2 SLSA Level 3 Build Attestation
Remediation workflows produce verifiable cryptographic provenance:
- **Source Integrity:** Commits verified via ephemeral GPG signatures.
- **Build Isolation:** Builds executed in isolated, ephemeral GitHub Actions runners without persistent cache poison vectors.
- **Hermetic Build Verification:** Sandboxed test runs disallow outbound network access to prevent dependency fetching during test cycles.

### 2.3 Automated Cryptographic Artifact Signing (Cosign / Sigstore)
All container images and release bundles generated by the remediation pipeline are signed with keyless Sigstore / Cosign:
```bash
cosign sign --yes \
  --oidc-provider https://token.actions.githubusercontent.com \
  ghcr.io/org/repo:patch-v1.4.2
```
